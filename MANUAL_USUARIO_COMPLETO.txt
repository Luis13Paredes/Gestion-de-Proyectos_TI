Tecnologias: React + Vite (frontend), Express + PostgreSQL (backend)

================================================================================
1. INTRODUCCION
================================================================================

El Gestor de Proyectos TI es una aplicacion web disenada para administrar
proyectos de Tecnologias de la Informacion enfocada en la metodologia Valor
Ganado (EVM). Permite planificar, ejecutar, monitorear y controlar proyectos
desde su acta de constitucion hasta el cierre, incluyendo gestion de riesgos,
calidad, equipo, costos, cronograma y cambios.

La aplicacion almacena los datos en una base de datos PostgreSQL, por lo que
todos los usuarios que accedan veran la misma informacion actualizada en
tiempo real.

2. REQUISITOS DEL SISTEMA
================================================================================

2.1 Requisitos de software
- Node.js 18 o superior (verificado con Node 20 y 24) y npm.
- PostgreSQL 12 o superior, instalado y corriendo localmente.
- Navegador web moderno (Chrome, Edge, Firefox).
- Acceso a internet (opcional, solo para el Asistente de IA mediante Groq).

3. INSTALACION Y PUESTA EN MARCHA
================================================================================

La aplicacion requiere DOS procesos corriendo al mismo tiempo: el backend y
el frontend.

Paso 1: Abrir dos terminales
Abre dos ventanas de terminal (PowerShell o CMD) en la carpeta raiz del proyecto:
  C:\Users\User\Desktop\PROYECTO FINAL_GESTION DE PROYECTOS\GESTION-PROGRAMA-main\GESTION-PROGRAMA-main

Paso 2: Levantar el backend (Terminal 1)
  npm run server
Deberas ver un banner confirmando que el servidor inicio en http://localhost:3000.

[CAPTURA 3.1: Terminal mostrando el comando npm run server y el banner de Servidor iniciado correctamente en el puerto 3000.]

Paso 3: Levantar el frontend (Terminal 2)
  npm run dev
Vite mostrara la URL local, normalmente http://localhost:5173.

[CAPTURA 3.2: Terminal mostrando el comando npm run dev y la direccion http://localhost:5173.]

Paso 4: Verificar funcionamiento
Abre en el navegador:
  http://localhost:3000/health
Debe responder algo como:
  {"status":"ok","timestamp":"...","databaseConfigured":true,"aiConfigured":true}

[CAPTURA 3.3: Navegador mostrando el endpoint /health con databaseConfigured: true.]

Importante: Si cierras las terminales, los servidores se detienen.
PostgreSQL permanece como servicio de Windows, por lo que no necesitas
reiniciarlo cada vez.

5. NAVEGACION GENERAL
================================================================================

La aplicacion tiene un sidebar oscuro a la izquierda con los modulos
disponibles. Al seleccionar un proyecto, aparecen sub-secciones dentro de
cada modulo.

Modulos principales:
1. Proyectos              - vuelve al Dashboard.
2. Resumen ejecutivo      - tablero con semaforos (CPI/SPI), reporte completo y Asistente de IA.
3. Acta y Alcance         - diagnostico, blueprint y acta formal.
4. EDT y Cronograma       - estructura de desglose, Gantt, ruta critica.
5. Equipo y Recursos      - matriz RACI y costeo.
6. Valor Ganado (EVM)     - fechas de corte, metricas, Curva S.
7. Evaluacion Economica   - TCO, ROI, payback.
8. Calidad                - auditorias, Pareto, CoQ.
9. Riesgos                - matriz P x I, EMV, arbol de decision.
10. Control de Cambios    - bitacora de solicitudes de cambio.

6. CREAR O EDITAR UN PROYECTO
================================================================================

Desde el Dashboard, haz clic en Nuevo Proyecto o selecciona un proyecto
existente y elige editar.

6.1 Informacion Basica
Llena los siguientes campos obligatorios:
- Nombre del Proyecto (minimo 3 caracteres, solo letras y simbolos permitidos).
- Descripcion (minimo 10 caracteres).
- Presupuesto Autorizado (BAC) - numero mayor a cero, maximo $10,000,000.
- Administrador del Proyecto y Asistente del Proyecto (opcionales, solo letras).
- Fecha de Inicio y Fecha de Fin Estimada (la fin debe ser posterior al inicio).

[CAPTURA 6.1: Formulario Informacion Basica del proyecto con todos los campos llenados.]

6.2 Equipo del Proyecto
Agrega al menos un miembro:
1. Escribe el Nombre del Miembro y su Rol.
2. Haz clic en Agregar.
3. Repite para todos los integrantes.

[CAPTURA 6.2: Seccion Equipo del Proyecto con miembros agregados.]

6.3 Planificacion de tareas (WBS)
1. Haz clic en Agregar fase y ponle nombre (ej. Analisis y Diseno).
2. Dentro de cada fase, haz clic en Agregar tarea.
3. Para cada tarea llena:
   - Entregable (obligatorio).
   - ID (ej. T-01-01).
   - Nombre de la tarea (obligatorio).
   - Tiempos PERT: Optimista, Estimado, Pesimista (dias).
   - Predecesoras - IDs de tareas previas separadas por coma (opcional).
   - Costo de la tarea.
   - Responsable (selecciona del equipo).

[CAPTURA 6.3: WBS con fases y tareas cargadas, mostrando tiempos PERT y predecesoras.]

[CAPTURA 6.4: Mensaje de Planificacion valida indicando que la ruta critica se puede calcular.]

4. Cuando termines, haz clic en Guardar Proyecto.

8. DETALLE DEL PROYECTO - ACTA Y ALCANCE
================================================================================

Tiene tres pestanas:

8.1 Diagnostico
- Arbol de problemas: Problema central, causas y efectos.
- Tecnica de las 5 preguntas clave (PMP): Que?, Por que?, A quienes afecta?, Cual es la consecuencia?, Que tan urgente es?.
- Justificacion: Pertinencia, urgencia, viabilidad e impacto.

[CAPTURA 8.1: Pestana Diagnostico con arbol de problemas, PMP y justificacion completos.]

8.2 Blueprint
Llena todos los campos:
- Proposito, objetivos medibles, alcance incluido y excluido, entregables, stack/arquitectura, supuestos, restricciones, hitos macro y criterios de exito.

[CAPTURA 8.2: Pestana Blueprint con todos los campos llenados.]

8.3 Acta formal
Muestra el acta de constitucion del proyecto. Puedes:
- Descargar como Markdown (archivo .md).
- Imprimir / Guardar como PDF (usando la funcion de impresion del navegador).

[CAPTURA 8.3: Acta formal generada con botones de descargar e imprimir.]

- Reservas: contingencia (riesgos conocidos, dentro de la linea base) y gestion (riesgos desconocidos, fuera de la linea base).

11. DETALLE DEL PROYECTO - VALOR GANADO (EVM)
================================================================================

Esta es una de las secciones mas importantes.

11.1 Agregar Fecha de Corte
Haz clic en Agregar Fecha de Corte y llena:
- Fecha: debe estar entre la fecha de inicio y fin del proyecto.
- % Completado: avance real del proyecto (0 a 100).
- AC devengado (USD): costo real acumulado.
- Compromiso pendiente (USD): ordenes de compra emitidas, aun no pagadas.
- Pagado (USD): desembolsos reales efectuados.

[CAPTURA 11.1: Formulario Nueva Fecha de Corte con los campos llenados.]

[CAPTURA 11.2: Lista de fechas de corte registradas con porcentaje y costo de cada una.]

11.2 Metricas EVM
Una vez hay una fecha de corte, veras:
- Valores Base: BAC, PV, EV, AC.
- Variaciones: CV, SV, CPI, SPI.
- Pronosticos: EAC (optimista, realista, pesimista, excepcional), ETC, VAC, TCPI.
- Curva S: grafico comparando PV (planificado), EV (ganado real) y AC (costo real).

[CAPTURA 11.3: Metricas EVM con CPI y SPI en rojo (proyecto en perdida).]

[CAPTURA 11.4: Curva S con lineas solidas (datos reales) y punteadas (proyeccion).]

Interpretacion rapida:
- CPI >= 1.0: dentro del presupuesto. CPI < 1.0: sobrecosto.
- SPI >= 1.0: a tiempo o adelantado. SPI < 1.0: retraso.

================================================================================

16. SOLUCION DE PROBLEMAS COMUNES
================================================================================

| Problema                          | Causa probable                     | Solucion                                               |
|-----------------------------------|------------------------------------|--------------------------------------------------------|
| No se pudo conectar con el servidor | Backend no esta corriendo         | Ejecuta npm run server en una terminal                 |
| Dashboard vacio                   | Solo levantaste un servidor        | Levanta ambos: npm run server y npm run dev            |
| EADDRINUSE en puerto 3000         | Algo usa el puerto 3000            | Cambia PORT en .env.local o cierra el otro proceso     |
| db:init falla al conectar         | PostgreSQL no esta corriendo       | Inicia el servicio postgresql-x64-18 desde Servicios   |
| Boton Analizar con IA da error    | Falta GROQ_API_KEY en .env.local   | Agrega la clave; el resto de la app funciona igual     |

17. GLOSARIO RAPIDO
================================================================================

| Termino         | Significado                                                           |
|-----------------|-----------------------------------------------------------------------|
| BAC             | Presupuesto Autorizado (cuanto se planeo gastar en total).            |
| PV              | Valor Planificado (cuanto deberia haberse gastado hasta hoy).         |
| EV              | Valor Ganado (cuanto trabajo real se completo, en dinero).            |
| AC              | Costo Real (cuanto se gasto realmente hasta hoy).                     |
| CV              | Variacion de Costo = EV - AC. Positivo = ahorro.                      |
| SV              | Variacion de Cronograma = EV - PV. Positivo = adelanto.               |
| CPI             | Indice de Desempeno de Costo = EV / AC.                               |
| SPI             | Indice de Desempeno de Cronograma = EV / PV.                          |
| EAC             | Estimacion al Completo (cuanto costara al terminar).                  |
| VAC             | Variacion al Completo = BAC - EAC.                                    |
| WBS/EDT         | Estructura de Desglose del Trabajo.                                   |
| RACI            | Matriz de responsabilidades (R, A, C, I).                             |
| Gantt           | Diagrama de barras del cronograma.                                    |
| Ruta critica    | Secuencia de tareas que determina la duracion minima del proyecto.    |
